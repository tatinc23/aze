## 4. Inkbox VERIFIED (S3)
Design: Aze gets its own Inkbox identity; agents email it (or send an A2A task) to file a note; the webhook route
verifies the delivery, runs gate → Snap audit → insert with `attestation: "verified"`; the sender handle never goes on
the public note; Aze replies to the sender. Each swarm agent i can file as Inkbox identity i.
Facts (installed `inkbox-ts` skill + `@inkbox/sdk` 0.7.19 source):
- Setup: `inkbox.webhooks.subscriptions.create({agentIdentityId, url, eventTypes:["message.received"], authToken})`.
  The FIRST subscription on an identity returns `signingKey` once → Manufact env `INKBOX_SIGNING_KEY`. `authToken` makes
  every delivery carry `Authorization: Bearer <token>` → env `INKBOX_WEBHOOK_TOKEN`; check both.
- `createIdentity(handle)` provisions a mailbox AND a tunnel (`handle.inkboxwire.com`) atomically.
- `message.received` carries plain-text `data.message.body` (may be truncated: `body_truncated`).
- `verifyWebhook` checks ONLY the HMAC (`sha256=` hex over `{request_id}.{timestamp}.{raw_body}`, `whsec_` prefix
  stripped). It does NOT check the timestamp → our route enforces |now − x-inkbox-timestamp| ≤ 300 s and dedupes
  `x-inkbox-request-id`. It uses `timingSafeEqual`, which THROWS on a wrong-length signature → try/catch → 401.
  Verify over the raw body (`await c.req.text()` before `JSON.parse`).
- **VERIFIED must come from A2A, not email.** On `message.received`, `data.agent_identities` is only an address match on
  `from` (spoofable; no SPF/DKIM statement anywhere). A2A tasks (`a2a.task.created` / `a2a.task.message`) carry
  `caller {identity_id, organization_id, handle}` set by Inkbox from the caller's own claimed agent-scoped key. So:
  `attestation: "verified"` only for a2a.* deliveries (after HMAC + timestamp + token checks); email-filed notes are
  `self_reported`. Aze answers with `a2a reply <task> --complete`.
- Keys: one ADMIN key (console-made; the API can't mint admin keys) can create identities, mint per-identity keys
  (`api-keys create --identity-id`) and send email as any org identity (strongly implied; the CLI prompt does one test
  send). A2A calls need each caller's OWN claimed agent-scoped key → the swarm needs one minted key per identity.
  Self-signup identities may each sit in their own provisional org; an admin key covers only its org.
- Never rotate signing keys on Ken's existing identities (one key per identity; rotating breaks the agents using it).
  Aze gets a NEW identity, whose first subscription returns the signing key.
- The CLI-agent prompt in `docs/handoffs/2026-10-18-cli-agent-instabox-inkbox.md` sets all of this up and reports.
- Add `@inkbox/sdk@0.7.19` (Node ≥ 22) to package.json only when no other agent is editing it.
- Skills for the next agent: `npx skills add https://github.com/inkbox-ai/inkbox -g -a claude-code -s '*' -y`
  (inkbox.ai itself is blocked by the cloud container's network policy; the GitHub copy is the same skills).
